## Purpose and scope

SPIFF ("SPHEREx Photometry and Image Fitting Framework") is a command-line/Python toolkit that discovers SPHEREx Level-2 exposures near a target coordinate (with optional proper-motion propagation), downloads or S3-cutout-streams each exposure, PSF-fits the source on each individual exposure with a floating (fittable) sub-pixel position, records the per-exposure detector wavelength at the fitted position, and finally combines all per-exposure measurements into an error-weighted mean spectrum on the 102 nominal SPHEREx spectral channels. It also ships a template-matching "autotype" tool that classifies late-M/L/T/Y dwarfs by comparison to a bundled spectral-template library. The intended targets are **point sources with proper motion** — brown dwarfs and ultracool dwarfs in the discovery paper — not resolved or extended sources; there is no galaxy/Sersic option anywhere in the code.

## Data access layer

- Discovery uses IRSA's SIA2 service (`query_obscore_sia2`, `src/spiff/lv2.py:1002`), querying with hard-coded default collections `("spherex_qr2", "spherex_qr2_deep")` (module constant `CATALOGS = ("spherex_qr2", "spherex_qr2_deep")` at `lv2.py:257`); a legacy TAP-based path `query_obscore()` (`lv2.py:1544`) defaults to older collection names `("spherex_qr","spherex_qr_deep")`, apparently a holdover from an earlier (pre-QR2) IRSA schema and not used by the SIA2 path. A CLI flag `--include-qr2-deep` (default on) appends `spherex_qr2_deep` to the collection list (`lv2.py:2874-3035`). There is no mention anywhere of `spherex_qr3` or a QR3/DR1 collection name — the tool is hard-wired to QR2-era IRSA collection identifiers.
- SIA2 responses are parsed defensively: because IRSA's SIA CSV can contain unescaped commas inside a `cloud_access` JSON blob (corrupting column alignment), the code strips comment lines, forces `index_col=False`, drops duplicate columns, and uses a fallback "predicate scan" (`_find_by_predicate`) to relocate columns like `access_url` or `t_exptime` if the expected header is missing or wrong (`lv2.py:1002-1148`) — adaptive to schema drift, useful if IRSA's SIA output changes again for QR3/DR1.
- File retrieval supports three paths: (1) direct HTTPS download via `curl`/`wget` with retry/backoff and transient-error classification (`_download_file_with_retries`, `lv2.py:495-902`); (2) anonymous S3 byte-range access via `s3fs` (`_download_file_via_s3`, `lv2.py:707`), the **default**; and (3) a byte-range "S3 cutout" mode (default 20×20 px) using `astropy.io.fits`'s `ImageHDU.section[...]` to fetch only the needed rows/columns per detector-plane extension without materializing the full frame (`_write_fits_cutout`, `lv2.py:640-706`) — the default, README-recommended mode. S3 keys are derived from the access URL by string manipulation (`_s3_key_from_fits_url`, `lv2.py:613`), hard-coded to the current QR2 bucket/key layout.
- DataLink resolution (`lv2.py:1165-1362`) batches up to 5000 IDs per request and retries with jitter to survive rate limiting.
- A local `download_manifest.csv` (`_append_download_manifest`, `lv2.py:425`) and a "predownloaded FITS inventory" scan (`_inventory_predownloaded_fits`, `lv2.py:432`) provide simple on-disk caching/resume so repeated runs do not re-download files already present in the output directory.

## Data model handling

- MEF extensions are accessed by **fixed integer index**, not by `EXTNAME`: `hdul[1]`=IMAGE, `hdul[2]`=FLAGS, `hdul[3]`=VARIANCE, `hdul[5]`=PSF cube, `hdul[6]`=WCS-WAVE table (`src/spiff/single_fit.py:338-374`). There is **no read of a ZODI extension anywhere in the codebase** (confirmed by grep — ZODI never appears), and no `EXTNAME`-based lookup, so the code would silently misbehave if IRSA ever reorders/renames extensions or inserts a new one (e.g., for an EPSF-based QR3 product with a different extension layout).
- PSF handling is **cube-only**: it assumes `hdul[5].data` is a 3-D `(nplane, ny, nx)` position-dependent PSF cube (QR2/pipeline-6.x style), selected by nearest detector position using per-plane `XCTR_n`/`YCTR_n` header cards (`src/spiff/spherex_psf_selection.py`). This module contains a specific, well-tested fix for a real IRSA header bug: SPHEREx PSF headers historically paired the `XCTR_n`/`YCTR_n` cards in y-fast order even though the cube itself is x-fast, and `select_spherex_psf()` reconstructs the independent axis grids and re-derives the correct plane index (returning a `dataclass` recording `selection_method`, `plane_index`, `zone_x_index`, etc. for provenance). **No code path reads a QR3-style `EPSF` binary table** (`BINX BINY XCENTER YCENTER NEFF_MEAN CWAVE CBAND EPSF`, 33×33, 5× oversampled) — `EPSF`/`epsf` never appears in the source. Migrating to QR3 EPSF products would require new code, not a config change.
- Flags: `hdul[2].data` is read and used as a bitmask via local `bit(n)` helpers and per-bit-count diagnostics (`single_fit.py:555-635`), but the code does **not** parse `MP_*` header keywords dynamically — bit semantics are hard-coded/assumed (e.g. `'NONLINEAR': 15` at `single_fit.py:569`), tied to the QR2 `MP_*` layout and not tracking a QR3 `MSKN`/`MSKM` scheme.
- Wavelength: SPIFF reads the **WCS-WAVE** table (extension 6) directly rather than using CWAVE/CBAND calibration files. It extracts `X`/`Y` coordinate grids and a `VALUES` array with two layers (center wavelength, channel width), auto-detects axis orientation (`_orient_value_layer`, `single_fit.py:395-420`), and bilinearly interpolates the wavelength (and its Monte-Carlo-sampled uncertainty, via `wcswave_sample_stats`) at the exact fitted detector position for every exposure and each of the three flux flavors (aperture COM, SciPy PSF fit, UltraNest PSF fit) separately (`single_fit.py:420-520`).
- Cutout-to-parent pixel mapping: the S3-cutout writer stores `SPXORX0`/`SPXORY0`/`SPXNX`/`SPXNY` header keywords recording the cutout's origin and the parent frame size (`lv2.py:690-698`), and shifts `CRPIX1`/`CRPIX2` accordingly. `spherex_psf_selection.detector_pixel_coordinates()` (`spherex_psf_selection.py:44-70`) then converts a local (possibly-cutout) pixel back to full-parent-detector pixel coordinates using, in priority order, `SPXORX0/SPXORY0` (its own cutout convention), then `CRPIX1A/CRPIX2A` (an alternate WCS key, matching the "alternate WCS key W" mentioned in the background note), then falls back to identity if neither is present.
- Solid angle: read from header keyword `HIERARCH OMEGA_MEDIAN` (arcsec²), not from a dedicated Solid Angle map extension/file (`single_fit.py:348-356`).

## Photometry / extraction method

- **PSF preparation** (`make_psf_cut`, `single_fit.py:1172-1216`): crop the oversampled PSF plane to a size divisible by `OVERSAMP` (typically 10), paste onto a zero-padded high-resolution canvas matching the cutout size, apply a cubic-spline sub-pixel `scipy.ndimage.shift` on the *oversampled* grid (order=3, `prefilter=True`) to place the model at the trial (dx, dy), then a **flux-conserving block-sum** (`.reshape(H, oversamp, W, oversamp).sum(axis=(1,3))`) down to detector resolution. The PSF is **not** renormalized to unit sum; instead the discrete sum (`psf_det_sum`) is tracked and folded into the flux-unit conversion (`single_fit.py:1234-1238`).
- **Background**: local median in an expanding box starting at 15×15 pixels (`box_size_bcg_subtract = 15`, `single_fit.py:162`), computed on flag-masked pixels (`_compute_background_with_expanding_box`, `single_fit.py:649-699`) with an automatic fallback to an unmasked median and box-doubling (up to 2 doublings) if masking leaves no usable pixels, and a second auto-retry that disables masking entirely if the box is still empty. This matches the "local 15-pixel background" behavior described in the background brief.
- **Fitting**: two sequential stages. (1) `scipy.optimize.minimize` (`L-BFGS-B`, with a `Powell` fallback) on a χ² objective (`chi2_scipy`, `single_fit.py:1301-1334`) gives a fast warm-start for flux, dx, dy. (2) If UltraNest is installed and `--scipy-only` is not passed, `ultranest.ReactiveNestedSampler` explores the same 3-parameter posterior with uniform priors centered on the SciPy solution (`single_fit.py:1731-1789`); the ML point and posterior-based uncertainties (median/MAD of samples) are recorded. Both flavors, plus classical aperture photometry over a grid of radii with COM centroiding (`aperture_metrics`, `single_fit.py:896`), are written to `results.csv` per exposure — three parallel flux estimates per exposure/channel (aperture, `psf_scipy_*`, `psf_un_*`).
- **Deblending**: none — single-PSF model only, no multi-source fit or neighbor subtraction.
- **Error propagation**: per-exposure flux uncertainty comes from the fit covariance (SciPy) or posterior spread (UltraNest); combination into the 102-channel grid uses inverse-variance binning (`build_binned_spherex_spectrum`, `src/spiff/spherex_binning.py:94-179`): nearest-bin assignment (searchsorted + left/right distance comparison), weight = 1/σ², weighted mean = Σ(f·w)/Σw, weighted SEM = √(1/Σw), with quality cuts on `min_snr` (default 0.1) and `min_n_pix_used_in_fit` (default 3). Fluxes convert µJy→`f_λ` via `c/λ²` (`_to_flambda_from_ujy`, `spherex_binning.py:48-51`).
- **Output format**: per-run outputs are `results.csv` (raw per-exposure/per-flavor measurements plus FITS/aperture metadata), `results.jsonl` (line-delimited JSON with covariances), `binned_spectrum.csv` (reduced spectrum: `bin_id, bin_center_um, bin_width_um, n_points, wavelength_angstrom, flux_ujy_weighted_mean, flux_ujy_weighted_sem, flux_flambda, flux_flambda_unc, ignored`), and a `download_manifest.csv`. The 102-channel grid itself is a bundled static table, `src/spiff/data/spherex_bins.csv` (103 lines including header = 102 bins), so no external bin-definition service is queried at runtime.

## Extended-source support

None. There is no Sersic/galaxy-morphology model, no elliptical-aperture option (apertures are circular, defined by a single radius, `aperture_metrics(r_px)`), and no aperture-correction table beyond the implicit PSF-fit flux (which is itself a total-flux estimate under a point-source assumption). Grep for "sersic", "galaxy", "extended", "elliptical", "apcorr" across `src/spiff/*.py` returns nothing. The tool is architecturally point-source only: the model image is always `flux * PSF(dx, dy)`, and the only free spatial parameters are a 2-D position offset, not a shape.

## Code quality

- **Structure**: reasonably modular (`lv2.py` = discovery/download/orchestration/CLI, `single_fit.py` = per-exposure PSF/aperture fitting, `spherex_binning.py` = channel binning, `spherex_psf_selection.py` = PSF-plane lookup, `autotype.py` = template classification, `results.py` = compiling per-image CSVs). However `lv2.py` (3124 lines) and `single_fit.py` (2184 lines) are very large single-file modules with many nested closures (e.g. `make_psf_cut`, `wcswave_eval_xy_fullimg` defined inside `analyze_file`), which makes unit testing individual numerical steps harder and raises the risk of subtle bugs in long functions.
- **Dependencies**: modest and mostly mainstream (`astropy`, `astroquery`, `pyvo`, `s3fs`, `numpy`, `pandas`, `scipy`, `matplotlib`, `joblib`); `ultranest` is an optional extra with an explicit `--scipy-only` fallback, so the package degrades gracefully without it.
- **Hard-coded paths**: none found (`grep` for `/Users/`, `/home/`, `C:\` returns nothing) — output paths are all CLI-configurable.
- **Robustness to schema drift**: the SIA2/discovery layer is unusually defensive about column-name drift (see Data access layer above). In contrast, the **FITS extension layout is fully hard-coded by index** and the **PSF model assumes a cube, never an EPSF table** — the single biggest robustness risk for a QR3/DR1 migration; a QR3 EPSF binary-table product would need a new PSF-preparation path, and `MSKN`/`MSKM` vs. `MP_*` flag renaming is not accounted for at all.
- **Tests**: reasonably targeted at the trickiest numerical logic (PSF-plane x-fast/y-fast reconstruction, binning arithmetic, S3 cutout header rewriting, JSONL round-trip), but no end-to-end test of `single_fit.analyze_file` (exercised only informally via the committed SIMP J0136 example products) and no CI on `main` (added only on the unmerged audit branch). Single author, no PR review visible in history.

## Reusable pieces for our project

- `src/spiff/spherex_psf_selection.py` (whole file, 171 lines): a clean, dependency-light, well-tested (`tests/test_spherex_psf_selection.py`) implementation of nearest-PSF-plane selection from a QR2 PSF cube, including the x-fast/y-fast header-pairing fix and the cutout-to-parent pixel-coordinate reconstruction (`detector_pixel_coordinates`, lines 44-70, handles `SPXORX0/SPXORY0` and `CRPIX1A/CRPIX2A` alternate-WCS cases). Directly reusable if we keep supporting QR2-cube PSFs, and a good template for a parallel EPSF-table selector we'd need to write for QR3.
- `src/spiff/lv2.py:640-706` (`_write_fits_cutout`): a good pattern for byte-range S3 cutouts using `ImageHDU.section[...]`, preserving/rewriting `CRPIX1/CRPIX2` and recording the cutout origin (`SPXORX0/SPXORY0/SPXNX/SPXNY`) — useful boilerplate for our own cutout tooling regardless of whether we reuse SPIFF's discovery layer.
- `single_fit.py:1172-1216` (`make_psf_cut`): the shift-on-oversampled-grid-then-block-sum PSF preparation logic is a solid, flux-conserving reference implementation worth adapting (their PSF-normalization convention — not renormalizing, but tracking `psf_det_sum` — is worth deciding explicitly for our own code rather than assuming unit-normalized PSFs).
- `single_fit.py:420-520` (WCS-WAVE bilinear interpolation + orientation auto-detection, `_orient_value_layer`, `_extract_wcswave_layers`, `wcswave_eval_xy_fullimg`, `wcswave_sample_stats`): directly reusable for per-pixel/per-position wavelength lookup, including Monte Carlo propagation of position uncertainty into wavelength uncertainty.
- `src/spiff/spherex_binning.py` (whole file, 196 lines): a compact, tested reference for nearest-bin, inverse-variance-weighted combination onto the 102 fixed SPHEREx channels and the µJy→f_λ conversion; useful either as a drop-in dependency or as a spec to reimplement against our own (likely per-source, PSF-model-based rather than per-exposure-photometry-based) flux estimates.
- `src/spiff/lv2.py:495-902` (retry/backoff and transient-vs-permanent error classification for TAP/SIA/S3/HTTP failures): useful operational hardening to borrow regardless of which discovery layer we build.

## Risks and limitations

- **QR3/DR1 incompatibility by construction**: hard-coded extension indices, QR2-only collection names (`spherex_qr2`, `spherex_qr2_deep`), PSF-cube-only model (no EPSF table support), and `MP_*`-flavored flag handling (no `MSKN`/`MSKM` awareness) mean SPIFF as-is will very likely break or silently misbehave once we switch to QR3 (7.0.x, since 2026-07-20) or DR1 (expected late 2026) products, unless these code paths are updated.
- **Point-source-only architecture**: not adaptable to resolved/semi-resolved galaxies without substantial rewriting of the model (would need a Sersic/extended-light model replacing the pure `flux * PSF` term, plus a different background/deblending strategy for extended, possibly clumpy light).
- **No ZODI handling**: the tool never reads or subtracts the ZODI model extension; its 15-pixel local-median background implicitly absorbs zodiacal light along with instrumental background, which is fine for faint point sources on a locally flat background but may not generalize to extended sources with structured backgrounds.
- **Single author, no external code review**: 11 commits, one contributor, no CI on `main`; correctness for edge cases (crowded fields, cutout edges, multi-plane PSF grids with missing headers) is asserted by unit tests on individual functions rather than integration tests of the full pipeline.
- **Absolute calibration caveat** (from the associated paper, not the code): the authors themselves recommend an ≈8% systematic flux-calibration error floor pending a fuller SPHEREx absolute-calibration characterization; the "preliminary" per-channel response function is applied without an obvious update mechanism in the code for future refined calibration files.
- **Runtime cost**: per the SPHEREx_pipeline README (an independent source), full SPIFF extraction (with UltraNest) can take "over two hours to extract a single source" — a real consideration for a sample of many post-starburst galaxies.
- **Un-merged fixes**: two commits on the `codex/audit-remediation-20260820` branch ("remediate SPIFF audit contracts", "preserve SPIFF spectral product values") are not in `main` as reviewed; it's worth checking that branch before depending on `main`'s exact numeric output.

## Verdict

**Borrow pieces.** SPIFF is not directly usable for resolved/semi-resolved post-starburst galaxies (point-source-only PSF model, QR2-only data-model assumptions, no galaxy morphology support), and its single-author/no-CI/no-PyPI status means it should not be depended on as an installed library. However, several isolated modules are high-quality, tested, and directly transferable to a custom pipeline: the PSF-plane selection logic and its detector-origin bookkeeping (`spherex_psf_selection.py`), the S3 byte-range cutout pattern (`_write_fits_cutout`), the WCS-WAVE per-position wavelength interpolation with uncertainty propagation, and the error-weighted 102-channel binning scheme. These are worth adapting into our own PSF-forward-modeling/background pipeline rather than depending on SPIFF as installed code, and the associated paper (arXiv:2604.22012) is a useful methodological reference (floating-position PSF fit, local background, per-exposure wavelength, 8% calibration-error floor) even where the code itself will need to be rewritten for extended sources and QR3/DR1 data.
