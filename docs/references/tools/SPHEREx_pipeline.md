## Purpose and scope

This repository is a two-part convenience pipeline layered on top of *other* tools, not an independent SPHEREx Level-2 reader. Part 1 ("source decontamination") cross-matches a target catalog against seven external, non-SPHEREx survey catalogs (Gaia DR3, DESI Legacy DR10, Pan-STARRS DR1, SDSS DR16, unWISE DR1, VISTA VHS DR5, DES DR2) and, for surviving targets, runs `photutils.detection.DAOStarFinder` on cutouts from the highest-resolution available optical/IR survey image (DESI→DES→Pan-STARRS→VHS→SDSS→DSS2 fallback chain) to flag SPHEREx-pixel-scale (9.3″ default radius) blending by unresolved neighbors. Part 2 ("spectrum querying and extraction") is a thin wrapper around the third-party `spxquery` package (`WenkeRen/spxquery` on GitHub, MIT-licensed) that performs SPHEREx's own fixed 3-detector-pixel (9.3″) aperture photometry, followed by an empirical, magnitude- and wavelength-dependent linear-regression correction (fit once by the author, hard-coded as slope/intercept pairs) rescaling `spxquery`'s aperture flux to approximate SPIFF's PSF-fit flux. Intended targets are **point sources** (brown dwarfs/stars, matching SPIFF's target class); there is no support for resolved or extended sources anywhere in the code or documentation.

## Data access layer

- **SPHEREx data itself is never read directly by this repository.** All SPHEREx pixel-level access (finding exposures, applying cutouts, reading MEF extensions) is delegated to the external `spxquery` package, invoked as `run_pipeline(ra=…, dec=…, source_name=…, output_dir=…, max_processing_workers=10, cutout_size="20px")` inside `pipeline/spxquery_wrapper.py:120-123`. `spxquery` is pinned loosely (`spxquery==0.2.2`) and was not reviewed here — its own data-access assumptions (IRSA release, SIA/TAP/S3, versioning) are inherited without override or abstraction.
- The "decontamination" half queries seven **non-SPHEREx** survey services directly: `astroquery.gaia.Gaia` (Gaia DR3 TAP), and (per `pipeline/catalog_contamination.py` function names) DESI Legacy DR10, Pan-STARRS DR1, SDSS DR16, unWISE DR1, VISTA VHS DR5, DES DR2, each via its own web service (`max_retries=3` per call). Image cutouts for the image-level check are similarly fetched from external survey cutout services (`pipeline/image_contamination.py:397-469`), not from IRSA/SPHEREx.
- No SPHEREx release version, collection name, or IRSA endpoint is hard-coded in this repo's own source (it lives inside the un-reviewed `spxquery` dependency). The wrapper does implement simple output-file caching: if `outdir/<source_id>.csv` already exists, `spxquery_get_spectrum_calibrated()` skips re-running the pipeline (`spxquery_wrapper.py:107-111`).

## Data model handling

Not applicable in any direct sense — this repository never opens a SPHEREx FITS file itself. There is no code here that reads IMAGE/FLAGS/VARIANCE/ZODI/PSF/EPSF/WCS-WAVE extensions, no flag-name handling (`MP_*` or `MSKN`/`MSKM`), no CWAVE/CBAND vs. WCS-WAVE wavelength choice, and no Solid Angle map or cutout-to-parent pixel-mapping logic — all of that is (or is not) implemented inside the external `spxquery` dependency. The only SPHEREx-specific numeric artifact defined here is a fixed wavelength binning grid used purely for the empirical calibration step: `STANDARD_BIN_EDGES = [0.74, 0.95, 1.15, 1.40, 1.65, 2.05, 2.45, 2.90, 3.50, 4.15, 5.05]` µm (10 bins, `pipeline/spxquery_wrapper.py:24`), coarser than and independent of SPIFF's 102-channel grid. Because all pixel-level extraction happens inside `spxquery`, robustness to a QR3 EPSF/flag-header change is entirely a function of whether `spxquery` itself has been updated.

## Photometry / extraction method

- **Base method**: fixed 3-detector-pixel-radius (9.3″) circular aperture photometry, performed entirely inside `spxquery.core.pipeline.run_pipeline`. This repo does not implement PSF fitting, background subtraction, or per-exposure combination itself; it only post-processes `spxquery`'s output CSV (`results/lightcurve.csv` inside a temporary per-source directory).
- **Empirical calibration** (`apply_calibration_to_dataframe`, `spxquery_wrapper.py:34-68`): for each output row, ten hard-coded `{slope, intercept}` pairs (`SAVED_CALIBRATION`, lines 12-22) are evaluated at `log10(flux)` for all 10 bins simultaneously, then linearly interpolated (`np.interp`, edge-clamped) to the row's exact wavelength to avoid bin-edge discontinuities; the per-row correction factor is floored at 1.0 ("Physics Clamp": corrections only increase flux) and applied to both `flux` and `flux_error`. This table was fit once by the author (fitting sample undocumented) and is **not** re-derivable or re-fittable from code here; it is a static, hard-coded lookup table.
- **Deblending**: none in the extraction step itself; deblending-like logic exists only in the separate contamination-flagging pipeline (Part 1), which is a pre-filter (exclude/flag contaminated targets) rather than a simultaneous multi-source fit.
- **Combination of exposures**: delegated entirely to `spxquery`; not implemented here.
- **Output format**: a per-source CSV (`outdir/<source_id>.csv`) preserving `spxquery`'s original `#`-comment header and columns (`wavelength`, `flux`, `flux_error`, …), plus three appended columns when `calibrate=True`: `flux_calib`, `flux_error_calib`, `correction_factor` (`spxquery_wrapper.py:139-176`). Temporary per-source working directories are deleted after the final CSV is written (`shutil.rmtree`), so no intermediate per-exposure products or diagnostics are retained.

## Extended-source support

None. Both halves of the pipeline are explicitly point-source-oriented: the contamination pipeline models the target as a point PSF with a fixed exclusion radius (9.3″, the SPHEREx pixel scale) and computes "dynamic PSF wings" for neighboring point sources based on survey FWHM and pixel scale (`pipeline/image_contamination.py`); the extraction wrapper uses a fixed circular aperture with a single empirical, flux-and-wavelength-dependent (not size/morphology-dependent) correction factor. There is no Sersic fitting, elliptical aperture option, or morphology-aware aperture correction — the calibration is a blanket point-source-to-point-source rescaling (`spxquery` aperture flux → SPIFF PSF-fit flux) with no dependence on source size or profile. Applying it to resolved/semi-resolved galaxies would be a methodological mismatch: it was derived to compensate for PSF-wing light lost by a fixed aperture around a point source, which has a different, source-size-dependent meaning for extended light distributions.

The empirical calibration table (`SAVED_CALIBRATION`) is itself release-specific — if `spxquery`'s SPHEREx data version or aperture definition changes, the hard-coded slope/intercept values would likely go stale with no code-level warning or provenance metadata.

## Reusable pieces for our project

- `pipeline/catalog_contamination.py` and `pipeline/image_contamination.py`: the general *pattern* of multi-survey, band-aware contamination flagging ("Omni-Band Threat Detection": only flag a neighbor as a threat if detected in a band overlapping SPHEREx's mid-IR range) and the magnitude-dependent image-level strategy (bypass DAOStarFinder for bright Gaia G<14 stars to avoid diffraction-spike false positives; saddle-point/profile-based deblending checks for fainter sources) are conceptually useful for our own neighbor-contamination checks, though point-source-specific and needing adaptation for extended host galaxies. `is_real_source()` (`image_contamination.py:91`) and `count_sources_in_image()` (`image_contamination.py:121`) are the most self-contained functions to start from.
- `pipeline/spxquery_wrapper.py:12-68` (the calibration-application *logic*, not the numbers): interpolating between per-bin calibration coefficients to get a continuous, edge-discontinuity-free correction as a function of wavelength is a reasonable pattern to reuse if we ever apply our own empirical corrections.
- Given the near-total delegation to `spxquery`, a more relevant follow-up for our project than this repo would be an independent review of `WenkeRen/spxquery` itself (out of scope here) if fast bulk aperture photometry is ever wanted as a cross-check against our own PSF-forward-modeled spectra.

## Risks and limitations

- **No direct control over SPHEREx data handling**: extraction is entirely delegated to `spxquery` (pinned to `0.2.2`); any assumptions it makes about SPHEREx release, MEF layout, flags, PSF/EPSF, or ZODI are opaque from this repo and were not verified here.
- **Fixed-aperture-only extraction with a static, non-reproducible calibration**: the core "spectrum" product is a fixed 3-pixel aperture flux corrected by a hard-coded linear regression fit once against SPIFF outputs for an undocumented calibration sample; there is no code to refit this table, no confidence intervals, and no indication of how it would generalize to a different flux regime, source class (e.g., resolved galaxies instead of point sources), or SPHEREx data release.
- **No license file**: reuse of substantial code should be cleared with the author first.
- **Unmaintained**: no commits since 2026-06-01, no tests/CI, no community activity (0 forks, 0 issues) — a frozen research snapshot, not an actively supported tool.
- **Point-source-only design throughout**: neither the contamination-flagging half nor the extraction/calibration half has any mechanism applicable to resolved or semi-resolved galaxy targets; applying the calibration correction factor to extended sources would be scientifically unjustified given how it was derived (fixed-aperture point-source flux lost to PSF wings).

## Verdict

**Read for ideas only.** This tool is not a SPHEREx Level-2 data-access or extraction library in its own right — it is a thin, unmaintained (frozen since 2026-06-01), untested, unlicensed wrapper around a third-party bulk-aperture tool (`spxquery`) plus a separate, useful-in-concept but point-source-specific neighbor-contamination checker built on external, non-SPHEREx survey catalogs and images. Nothing here reads SPHEREx MEF extensions, PSF/EPSF products, flags, or ZODI directly, so it offers no code transferable to our own PSF-forward-modeling and background-handling pipeline for resolved/semi-resolved galaxies. The multi-survey, band-aware contamination-flagging *strategy* (not the code) is worth remembering if point-source interlopers become a concern, but the extraction/calibration half should not be used for extended sources.
