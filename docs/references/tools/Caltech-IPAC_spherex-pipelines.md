## What is public and what is not

This is a genuine, essentially-complete snapshot of the internal L1-3 pipeline, not a stub. Every L3 task named in the pipeline paper (Akeson et al. 2026) is a real `PipelineTask` in `py_src/spx_tasks/`: `perform_forced_photometry.py`, `estimate_diffuse_background.py`, `create_source_mask.py`, `get_zodi_model.py`, `estimate_psf.py`, `measure_psf.py`, `query_reference_catalog.py`, `create_spectral_image.py`, `l3a.py` (orchestrator). L1/L2 modules (dark current, non-linearity, persistence, bad-pixel masking, astrometry, absolute gain, variance map, BSH/crosstalk/ghost flagging, DQA) are equally detailed.

Explicitly **not** public: spacecraft telemetry/downlink handling; the **Data Simulator** and **shared system-engineering parameters** — `get_zodi_model.py` imports `SPHEREx_SkySimulator as SPsky`/`SPHEREx_InstrumentSimulator as SPinst` inside a `try/except ImportError` guard (`hasSPHERExSimulator`), raising `ImportError` if absent; the `[extra]` group references `git+https://github.com/SPHEREx/SPHEREx-Sky-Simulator@main` and `.../SPHEREx-Parameters@main` (possibly public repos, not verified here, not cloned); internal Butler registry/credentials to actually execute at IPAC/TACC; the internal Jira-tracked commit history (public repo receives discrete "Import release X+public.N" snapshots, referencing non-browsable `jira.ipac.caltech.edu` tickets). No named module was found to be a stub with no logic — the gaps are in the execution environment, not the algorithms.

## Level 3 photometry in detail

**Task**: `PerformForcedPhotometryTask`, `py_src/spx_tasks/perform_forced_photometry.py` (769 lines), doc tag `SSDC-MS-033 3.1`, orchestrated with `EstimateDiffuseBackgroundTask` by `L3aTask` (`py_src/spx_tasks/l3a.py`, YAML `pipelines/L3aPipeline.yaml`).

**Inputs**: L2 `SPHERExImage`, global background (`numpy.ndarray`, all-NaN if failed), deferred-load reference catalog (Parquet), per-detector `solid_angle_pixel_map`, optional per-detector `spectral_wcs` (`CWAVE`/`CBAND`; falls back to Simulator's `DetectorSpectralInfo` if absent, `use_simulator_bandpass` config).

**Algorithm** (`run()`):
1. Read minimal catalog columns (`cat_phot_cols` default: `SPHERExRefID, ra, dec, ra_error, dec_error, ref_ra, ref_dec, sersic, shape_r, ab_ratio, phi, for_l3phot`).
2. Extract/record refcat provenance/version.
3. WCS-convert RA/Dec to detector pixels; keep on-image sources (0.5-px edge tolerance); if present, further filter to `for_l3phot == 1` (keeps galactic-plane sources in L3 photometry without polluting the bright-star mask).
4. Assign HEALPix `hips{order}` index (default `hips_order=6`), preferring `ref_ra/ref_dec`.
5. **Pixel masking for Tractor** (which has no native masking): pixels flagged `SUR_ERROR|NONFUNC|MISSING_DATA|HOT|COLD|NONLINEAR|PERSIST|BLOOM|SNOWBALL|HALO|SATELLITE_HALO` are zeroed in data, variance set to `1e3*max(variance)`; non-finite/zero-variance pixels get similar sentinel treatment.
6. **Background branch**: if global background is all-NaN, `use_local=True` (local subtraction per window); else subtract global background from the whole image up front.
7. **Sliding-window tiling** (`spx_utils/photometry/window_utils.py:slide_window`): active area tiled into `cut_side_length`×`cut_side_length` cells (default **5×5 px**, must evenly divide active-pixel count). Interior cells padded by `frame_width` (default **3 px**) on non-edge sides → up to 11×11-px fitting windows; frame sources are modeled jointly but not recorded unless `keep_frame_sources=True`. If local background needed, an additional `bkg_side_length`×`bkg_side_length` cutout (default **15×15 px**) surrounds each window — the "local 15×15 mode." `validate()` enforces `frame_width < cut_side_length`, `bkg_side_length > cut_side_length` with even difference, `bkg_box_size` divides `bkg_side_length`.
8. **Per-window local background** (`estimate_loc_bkg`, if `use_local`): 15×15 `Cutout2D`, sigma-clip (`sigma_lower=sigma_upper=4, maxiters=10` default), `photutils.background.Background2D(box_size=3, filter_size=(3,3), exclude_percentile=50.0)`; cut back to window footprint and subtracted before fitting.
9. **Tractor fitting** (`run_tractor_window`→`tractor_fit_spherex`, `spx_utils/photometry/tractor_utils.py`): one `tractor.PointSource` (if `sersic<1` or `not fit_shapes`) or `tractor.sersic.SersicGalaxy` (default `fit_shapes=True`) per source. Extended shape = `GalaxyShape(shape_r, 1/ab_ratio, position_angle)` (LS/Tractor convention: `shape_r`=half-light radius in arcsec, `ab_ratio`=axis ratio, `phi`=PA rotated into detector frame via WCS handedness (`np.linalg.det(wcs.pc)`)), `SersicIndex(sersic)`. **All positions frozen** (`freezeAllRecursive()` then `thawParam("brightness")`) — pure flux-only forced photometry. One `tractor.Image` per window: `NullWCS(pixscale=...)`, `LinearPhotoCal(1.0)` (flux units = MJy/sr), `ConstantSky(0.0)`, weights `1/variance`. `optimize_forced_photometry(variance=True)` returns flux + variance.
10. **Per-source flag aggregation/quality** (in `tractor_fit_spherex`): a 2.5-px-radius aperture (`regions.CirclePixelRegion(...,radius=2.5).to_mask(mode="center")`) around each source gives `fit_ql` = mean `|residual|/sqrt(variance)`, and OR-reduces all `Flag` bits present into the output `flags` column. If any pixel carries `TRANSIENT|OVERFLOW|SUR_ERROR|NONFUNC|DICHROIC|MISSING_DATA|HOT|COLD|NONLINEAR|CROSSTALK|GHOST|GHOST_FPA|GHOST_EXT|STREAK|PERSIST|BLOOM|SNOWBALL|HALO|SATELLITE_HALO` (broader than the Tractor-ignore list), `PhotometryFlag.CONTAINS_BAD_PIXEL` (bit 32) is set; NaN flux/error → `fit_ql=NaN` + `PhotometryFlag.FIT_ERROR` (bit 33).
11. **Combine windows** into one structured array (`combine_measurements`).
12. **Flux conversion** (`MJysr_to_uJy`): `flux_uJy = flux_MJysr.to(uJy/arcsec^2) * solid_angle_pixel_map[y,x] / oversample^2`, `oversample=1` passed here (code comment: "Tractor result flux was concentrated in a single 6.2″×6.2″ pixel") — the solid-angle map (arcsec² per detector pixel from Update Field Distortion) directly converts specific intensity to flux density.
13. **Wavelength**: nearest-pixel lookup of each source's *fitted* position into `spectral_wcs["CWAVE"/"CBAND"].data[y,x]` (or Simulator fallback) — i.e. CWAVE/CBAND at the fitted detector position, not a catalog value.
14. **Output** (Parquet, per-HEALPix or combined): `source_id, ra, dec, x_image, y_image, mjd, lambda, lambda_width, flux, flux_err, flux_bkg, local_bkg_flg, ext_flg, flags, fit_ql, deep_flg, lvf_id, det_id, hips{order}` (flux/err in µJy, flux_bkg in MJy/sr). Metadata: `version_level2`, `version_phot_meas` (`SSDC_PIPELINES_VERSION`), `refcat_version`.

**Defaults**: `cut_side_length=5`, `frame_width=3`, `bkg_side_length=15`, `bkg_box_size=3`, `bkg_filter_size=(3,3)`, `bkg_exclude_pct=50.0`, `bkg_sc_sigma_lower/upper=4`, `bkg_sc_maxiters=10`, `hips_order=6`, `fit_shapes=True`, `class_filter=ALL`. All are overridable `lsst.pex.config.Field`s.

**Sersic support**: real, default-on. No explicit size cutoff (unlike the IRSA tool's documented 20″ `Re` limit) — any `sersic>=1` source becomes a `SersicGalaxy`; practical limit is window geometry (11×11 px ≈ 68″) and FFT rendering cost.

**3% systematic term**: not found anywhere in this repo (`grep`ped for `0.03`, `systematic`, `sys_err` across `py_src/`). Per-pixel errors (`create_variance_map.py`) come from a Poisson+read-noise MLE of the up-the-ramp fit (Robberto 2007), propagated via `optimize_forced_photometry(variance=True)`. If a flat systematic floor exists, it is not a literal constant here — likely documented only in the Explanatory Supplement/paper, or applied downstream. Do not assume it is baked into `flux_err`.

## Background and zodi modules in detail

**Estimate Diffuse Background** (`EstimateDiffuseBackgroundTask`, `estimate_diffuse_background.py`, `SSDC-MS-032 v3.0`) — produces the **global** layer:
1. Mask flagged/source pixels (`OVERFLOW|SUR_ERROR|NONFUNC|MISSING_DATA|HOT|COLD|NONLINEAR|PERSIST|OUTLIER|CROSSTALK|SOURCE|GHOST*|STREAK|BLOOM|SNOWBALL|HALO|SATELLITE_HALO`).
2. **Global spectral component**: bin unmasked pixels by per-pixel wavelength (`CWAVE` or Simulator's `get_wavelength_mesh`), fit a smoothing spline (`scipy.interpolate.make_smoothing_spline`, `lam=0`) of flux vs. wavelength (reusing `define_spectral_bins`/`compute_avg_flux_and_wavelength` from `estimate_abs_gain_matrix.py`), evaluate onto the full 2D grid — captures the diffuse continuum's spectral shape rather than fitting the physical Kelsall model directly.
3. **Region-quality gate**: tile into `box_size` (default **(40,40)**) boxes, require ≥`pct_good_regions=90%` below `exclude_percentile=75%` masked fraction, else skip the spatial component (or return all-NaN if the spline fit itself fails).
4. **Diffuse component**: `Background2D(box_size=(40,40), SigmaClip(3,3,10), filter_size=(3,3), exclude_percentile=75.0)` on the spectral-subtracted image.
5. **Self-consistency**: sigma-clipped median of the residual must satisfy `|median| < sc_median_thresh=2e-3`, else discard (all-NaN → forces local 15×15 fallback in Perform Forced Photometry). This two-tier design (global spectral+`Background2D` 40×40 vs. local `Background2D` 15×15) is exactly the "global spectral zodi fit + `Background2D`, local 15×15 mode" expected.

**Get Zodi Model** (`GetZodiModelTask`, `get_zodi_model.py`, `SSDC-MS-022 v2.3`, L2) — the "Zodi Prediction module." Does **not** implement Kelsall itself: calls `SPHEREx_SkySimulator.zodicalc.ModifiedKelsallModelWithHPFT()` (external, guarded by `hasSPHERExSimulator`) at a subsampled grid (`zodi_subsample=15` px default), gets bandpasses via `SPHEREx_InstrumentSimulator.Instrument(...).pixel_to_band`, bandpass-averages, then bicubic-spline-interpolates (`RectBivariateSpline`, degree 3) to full resolution. Result stored as a `Zodi` object (`spx_data/zodi.py`) with `ZODIMDL` header keyword (matches observed `KEL98_WAVESCL_V1`) — but the wavelength-rescaling logic lives entirely in the non-public-here `SPHEREx_SkySimulator` package. Confirms `IMAGE` is not zodi-subtracted at L2 — this task only appends a `zodi` layer, nothing subtracts it from `spximg.data`.

## Source mask and reference catalog handling

**Create Source Mask** (`create_source_mask.py`, 1540 lines): per-detector bad-region mask combining bright-star wings, DBS ghosts, crosstalk, Band-4 bleed.
- **Radius-vs-magnitude**: `blended_exponential_radius(m,a1,b1,a2,b2,m0,w) = exp((1-s)(a1+b1·m)+s(a2+b2·m))`, `s=sigmoid((m-m0)/w)` — smooth blend of two log-linear regimes around `m0` (references an internal calibration logbook, `20251205_BrightStarMasking`). Per-detector coefficients hardcoded, e.g. `blended_radius_params_det1=[6.020,-0.2364,1.623,-0.048,10.175,2.112]` through `det6`. `mask_sources()` applies per source in `mag_det{band}` between `minmag=-5.0`/`maxmag=19.0`, draws `regions.CirclePixelRegion` masks, thresholds co-added exact-mode mask fraction at `masking_th=0.24`. A separate legacy discrete radius table (`masking_radii_det{1..6}` indexed by `brightness_cuts=[5.5,...,20.5]`) also remains in the config.
- **spherex_class**: bitmask (`SourcePipelineClass` `IntFlag`, `py_src/spx_utils/image_catalog.py`): `ASTROMETRIC(1<<0), PSF(1<<1), PHOTOMETRIC(1<<2), CALSPEC(1<<3), BRIGHT(1<<4), COSMOLOGY(1<<5), ICES(1<<6), NO_ICES(1<<7), SECONDARY(1<<8), STELLAR(1<<9), CLUSTER(1<<10), SNR_CUT(1<<11)`, plus `ALL`. Written by `query_reference_catalog.py` (`spherex_class_bitmask = ASTROMETRIC|PSF|PHOTOMETRIC|CALSPEC|BRIGHT`, combined with Gaia-ID presence and `NO_ICES` exclusion); consumed as the `class_filter` in Perform Forced Photometry (default `ALL`) and for per-window class filtering.
- Also in this task: `mask_crosstalk` (coupling matrix, `xtalk_amplitude_thresh=1e-4`, `limiting_xtalk_current=400.0`), DBS main/edge ghost masking (per-detector ROIs, `ghost_radius=52` px), Band-4 bleed (`band4_bleed_flux_thresh=3000.0`). `mask_ghosts=True`, `mask_xtalk=False` by default.
- **Query Reference Catalog** (1038 lines) assembles `srccat` from planned observations (not L1 images, `SP-1722`), including `for_l3phot` (`SP-1881`).

## PSF/ePSF handling in detail

**Data model** (`PSFZoneData`, `spx_data/psf.py`, 518 lines): per-detector PSF as a 3D "zone cube" — one oversampled kernel per (x,y) zone on an `x_zones×y_zones` grid (Estimate PSF default `bins_x=bins_y=11` → 121 zones, matching the "121×101×101" cube in real QR2 files), plus zone centers and `oversampling` (default **10**, matching QR2's 10×-oversampled product). FITS round-trip via `ImageHDU` with `XCTR_n/YCTR_n/XWID_n/YWID_n/OVERSAMP` keywords.

**Sub-pixel interpolation** (`get_blended_psf(x,y)`): finds the bracketing "quad" of four zone centers (`_get_inner_rectangle`, built via `_get_psf_quads`, extrapolating at edges using zone edges not centers), bilinearly blends the four corner kernels by inverse-area weights (`_get_dist_weights`) via a Numba-JIT tensor-dot (`manual_dot`) — smooth spatial variation at any position, not just zone centers.

**Loading + shift + downsample + normalize for Tractor** (`SPHERExTractorPSF.getPointSourcePatch`, `spx_utils/photometry/tractor_utils.py`): (1) `get_blended_psf` at the source's true detector position; (2) compute fractional oversampled-grid offset, split integer/sub-pixel parts; (3) sub-pixel shift via `tractor.psf.lanczos_shift_image` (Lanczos-3, from `tractor-spherex`); (4) zero-pad to align to the oversampling grid; (5) **downsample** with `cv2.resize(..., INTER_AREA)`; (6) **normalize** (`outimg /= outimg.sum()`); (7) return a `tractor.patch.Patch` at the correct integer origin. For Sersic sources, PSF convolution instead uses the FFT path (`getFourierTransformHiRes`) inside `tractor-spherex`'s monkey-patched `getUnitFluxModelPatchSPHEREx` (see companion note).

**PSF estimation** (`EstimatePSFTask`, `estimate_psf.py`): `bins_x=bins_y=11`, `cutout_size=11` px, `oversample=10`, Richardson-Lucy deconvolution with **per-detector iterations** `{1:7,2:6,3:7,4:7,5:6,6:7}`, stars `min_mag=11.0` to `max_mag=15.0`, `run_parallel=True`. This is the source of the QR2-style 10×-oversampled cube; the exact task that repackages it into the public QR3 EPSF binary table (5×, 33×33) was not located in `py_src/spx_tasks/` in this pass — worth a follow-up with a fuller (non-shallow) clone.

## Wavelength assignment (CWAVE/CBAND)

Canonical solution: the **Spectral WCS** product (`spx_data/spectral_wcs.py`, class `SpectralWCS`), a FITS `WAVE-TAB` alternate WCS with lookup extension `WCS-WAVE` (`SpectralWCS.LKPTBL_EXTNAME`), built at a coarse grid (`spectral_lookup.py`, default `n=7` → 7×7 points, ~340-px spacing) via `DetectorSpectralInfo.get_wl_mid_fwhm`. Passed into L3 tasks as `spectral_wcs` (`AstropyImage` `HDUList`), consumed as **already-expanded full-resolution images** under `CWAVE`/`CBAND`, indexed by integer pixel: `spectral_wcs["CWAVE"].data[y,x]` in both `perform_forced_photometry.py` (at each source's *fitted* position, `world_to_array_index`) and `estimate_diffuse_background.py` (binning the whole image). Falls back to `DetectorSpectralInfo` (Simulator) if absent (`use_simulator_bandpass=True`). One spectral solution per detector (`isCalibration=True`, `dimensions=["instrument","detector"]`), applied identically to every exposure from that detector — no per-exposure CWAVE/CBAND re-derivation in L3.

## Other modules relevant to us

- **Mosaic Tool** (`spx_apps/mosaic_tool/`, CLI `mosaic-tool create-mosaic`): TAN-projection mosaics from L2 LVF images. `--center`, `--size` (max 5°), `--rotation`, `--pixel-scale` (default/min 6.15″, no super-resolution), `--channel-range`/`--user-channels` (both restricted to `[0.75,1]` µm in this CLI help — possibly a documentation artifact worth cross-checking against the live tool), `--time`, `--detector`. Reads L2 from `SPXMOSAIC_INPUT_COLL` (default `IRSA-qr2-visible`)/`SPXMOSAIC_CALIBRATION_COLL` (default `IRSA-qr2-tools`). Whether/how it subtracts `ZODI` was not directly traced in this pass.
- **Create Spectral Image** (141 lines) / **Create Data Cube** (84 lines): short, present, non-trivial; not traced in full detail here.
- **DQA**: `dqa_l1/l2/l3.py`, `spx_utils/dqa_utils.py`, `log_dqa_result` — structured QA metrics used across tasks (e.g. `FINAST` fine-astrometry flag checked by `l3a.py` to skip L3 for failed exposures).
- **`spx_apps/photometry_tool/`** is the actual **IRSA Spectrophotometry Tool** backend: CLI `photometry-tool perform-photometry`, `--point ra,dec[,name]` or `--elliptical ra,dec,sersic,ratio,pa,effrad[,name]`, `--bkg-region` (**default 15**, matching the pipeline's local-background default), `--fit-positions/--no-fit-positions` (documented "Not implemented" — always frozen). Independently confirms the 15-px local background and frozen-position design as the live tool's actual behavior.

## Reusable pieces for our project

- **`spx_utils/photometry/tractor_utils.py`** (`tractor_fit_spherex`, `SPHERExTractorPSF`, `MJysr_to_uJy`) and **`window_utils.py`** (`slide_window`, `estimate_loc_bkg`, `run_tractor_window`) are the most valuable: a compact reference for building the PSF object with correct shift/downsample/normalize semantics, constructing frozen-position Tractor sources with the right parameter conventions, running `optimize_forced_photometry`, aggregating flags/quality, and converting MJy/sr→µJy. Only import `astropy`, `regions`, `cv2`, `numpy`, `tractor` — **no Rubin-Butler dependency** — realistically adaptable to a standalone script.
- **`spx_data/psf.py` (`PSFZoneData`)**: directly reusable/importable (only `astropy`, `numba`, `numpy`) for reading/blending a per-zone PSF cube; the bilinear zone-blending and edge-extrapolation logic is non-trivial and worth borrowing even if we ultimately work from the public ePSF FITS extension.
- **`create_source_mask.py`**'s `blended_exponential_radius()` and per-detector coefficients: directly reusable for a bright-star exclusion model consistent with the official pipeline.
- **`window_utils.py:estimate_loc_bkg`**: a clean ~20-line reference for the exact local-`Background2D` config, Butler-independent.
- **Reality check**: `spx_data`/`spx_utils` are largely middleware-free and plausibly vendorable; `spx_tasks`/`spx_apps` are tightly Butler-coupled and impractical to run standalone. Best path: read the task `run()` logic for exact parameters/control flow, reimplement against our own array-based pipeline, calling into `spx_data`/`spx_utils`/`tractor-spherex` where the import graph allows.

## Risks and limitations

- No guaranteed correspondence between the four same-day-pushed tags and the specific QR2/QR3/DR1 release we analyze — check `VERSION`/`SSDC_PIPELINES_VERSION` semantics against our actual files before trusting a parameter default.
- Zodi and `use_simulator_bandpass` fallback paths need non-public `SPHEREx_SkySimulator`/`SPHEREx_InstrumentSimulator`; public-availability of those repos not verified here.
- PSF-product provenance gap: located the internal 10×-oversampled `PSFZoneData` cube but not the task repackaging it into the QR3 5×/33×33 EPSF table; don't assume the two are identical.
- 3% systematic term not located — see Level 3 section.
- `CreateSourceMaskConfig` mixes legacy per-bin and newer blended-exponential radius schemes; verify which applies to a given pipeline version.
- Cannot execute or test anything here without the LSST/Rubin middleware and an SSDC-internal Butler; this is static code reading only.

## Verdict

**Borrow pieces (photometry/PSF utilities) + read closely for the rest.** `spx_data`/`spx_utils` (`tractor_utils.py`, `window_utils.py`, `psf.py`, `image_catalog.py`, `spectral_wcs.py`, `zodi.py`) are detailed and largely middleware-independent — worth adapting directly. `spx_tasks`/`spx_apps` are not directly runnable due to the Butler dependency but are an exact algorithmic specification (parameters, control flow, validation) to reimplement against. Given the "no external support" stance and snapshot-only publication, plan around reading this as ground truth and reimplementing relevant pieces standalone, cross-checked against the Explanatory Supplement and pipeline paper — not around running it end-to-end.
