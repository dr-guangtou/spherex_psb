## Purpose and scope

A small, self-contained toolkit for pulling a low-resolution SPHEREx spectrophotometric SED at a single user-specified sky position. Given an RA/Dec, it queries IRSA TAP for all overlapping SPHEREx Level-2 spectral images, retrieves small cutouts (via IRSA's cutout service or directly from the public `nasa-irsa-spherex` S3 bucket), assembles them into one multi-extension FITS "bundle," performs simple circular-aperture photometry with local annulus background subtraction on each cutout, and bins the resulting per-exposure flux densities into a coarser wavelength grid. The intended target is exclusively **point sources**: stars, quasars, and "DESI" galaxy IDs that are nonetheless treated as unresolved (fixed few-pixel aperture at the target coordinate, no morphology model). No support for extended/resolved galaxies, moving objects, or maps — the pipeline works one coordinate at a time and returns one 1-D spectrum.

## Data access layer

- **Discovery**: `search_lvfs()` (~line 88) queries IRSA TAP (`https://irsa.ipac.caltech.edu/TAP`, hard-coded default) with an ADQL query against `spherex.artifact`/`spherex.plane`, selecting bandpass, time bounds, and `uri` for all L2 images whose footprint contains the target point. `tap_search()` wraps this with retry logic (3 retries, 5 s delay) via `pyvo`. `maxrec` defaults to 5000 with an overflow warning if hit — a real risk for deep, well-observed fields with many exposures.
- **Retrieval**: two paths, toggled via a `REPO = "IRSA" | "CLOUD"` string in the tutorial. `get_links()` (~line 33) builds both an IRSA HTTP URL and an S3 URI (hard-coded bucket `"nasa-irsa-spherex"`) from the TAP `uri` column. `process_cutout_irsa()` (~line 331) appends `?center=<ra>,<dec>d&size=<deg>d` and calls `fits.open(uri)` directly on the HTTP cutout-service URL (up to `NTRIES=5`, `SLEEP=2` s; tutorial overrides to 15/1.5). `process_cutout_s3()` (~line 178) opens the *full* parent MEF anonymously via `fsspec` and uses `Cutout2D` on `hdul[key].section` to extract a local cutout, recomputing the WCS. Both paths are parallelized with `ThreadPoolExecutor`.
- **Release assumption**: nothing names "QR2," "QR3," or a pipeline version. The one release hint is a comment in `load_flag_info()` pointing to the QR-era Explanatory Supplement PDF, suggesting the flag-bit table was built against QR2 (pipeline ≤6.5.7) and is not release-aware.
- **Caching**: `cache=False` is threaded through `fits.open()` but never turned on in the tutorial; no on-disk cache management, no re-download avoidance, no checksumming/versioning.

## Data model handling

- **Extensions read**: only `IMAGE`, `FLAGS`, `VARIANCE` by default. **`VARIANCE` is downloaded and bundled but never actually read in the photometry/error code** — `measure_spherex_flux_helper()` (~line 605) only pulls `IMAGE`/`FLAGS` data; VARIANCE is dead weight as written.
- **PSF vs EPSF**: neither is ever opened (verified by grep across the repo) — pure aperture photometry with no PSF model, so the QR2-vs-QR3 PSF/EPSF format change is a non-issue simply because the tool never touches PSFs.
- **ZODI**: not referenced anywhere; `IMAGE` is used as-is (unit conversion only), so any un-subtracted zodi contribution is not handled.
- **Solid Angle map**: not used; `mjsr_to_jypixel()` (~line 528) hard-codes a fixed **6.15″** pixel scale for every band/detector, ignoring per-pixel/per-band solid-angle variation.
- **Flags**: a fully **hard-coded** bit-name table in `load_flag_info()` (~line 1101, 20 `(name, bit)` pairs from the QR Explanatory Supplement). `decompose_flags()`/`check_flags()` (~line 1132) then reject a measurement if any bad bit appears in the aperture. **The FITS header's own `MP_*` (QR2) or `MSKN`/`MSKM` (QR3) keywords are never read** to map bit names dynamically — the table is baked into source, so it will silently mis-map flags if bit assignments change between pipeline versions, with no fallback and no commit through 2026-08-20 addressing this.
- **Wavelengths**: from the **WCS** alone, not CWAVE/CBAND. Both cutout functions build `WCS(hdul["IMAGE"].header, fobj=hdul, key="W")` (explicitly the alternate WCS, key `'W'`), set `sip=None`, and call `pixel_to_world(x, y)` at the target pixel — exactly the WCS-WAVE-style approach the task background flags as non-authoritative; grep confirms zero hits for "cwave"/"cband" anywhere in the repo.
- **Cutout-to-parent mapping**: for the S3 path, `Cutout2D(..., mode="partial", fill_value=0.0)` handles this properly and the cutout WCS is written back to the header. For the IRSA path, mapping is delegated entirely to IRSA's server-side cutout service with no independent verification.

## Photometry / extraction method

Simple circular-aperture photometry with local annulus background subtraction — not PSF fitting, not Tractor forced photometry. `measure_spherex_flux_helper()` (~line 605) converts `IMAGE` from MJy/sr to mJy/pixel, builds a `CircularAperture` at the geometric center of the cutout (assumes the target is already centered by the cutout step, no re-centroiding) and a `CircularAnnulus` for background (tutorial defaults: aperture radius 1.5–3 px, annulus width 3 px). **PSF preparation**: none. **Background**: `ApertureStats` with `SigmaClip(sigma=3.0, maxiters=10)` on the annulus, sigma-clipped **median** scaled by `aperture.area_overlap` and subtracted — a genuine local annulus estimate, but with an annulus width of only a few pixels (order tens of arcsec), quite different from the IRSA tool's 15-pixel local background box. **Deblending**: none; a contaminating source in the annulus is only implicitly handled via sigma-clipping. **Flag rejection**: all-or-nothing per measurement — any bad bit anywhere in the aperture sets `good_photo=False` rather than masking individual pixels. **Error propagation**: no per-pixel VARIANCE-based propagation, and no 3% systematic term anywhere (grep confirms no `0.03`/systematic language). The only uncertainty is a **bootstrap standard deviation of the median** across per-exposure fluxes in each output bin (`bootstrap_median_std()`, ~line 862, 200–1000 resamples) — a purely empirical scatter estimate, not a formal error budget. **Combining exposures**: `bin_spherex_flux()` (~line 767) bins per-exposure `(lambda, flux)` pairs from `good_photo=True` measurements into fixed-width bins (0.1–0.3 µm as used in the tutorial), sigma-clips (3σ) within each bin, and takes the median flux plus bootstrap uncertainty; bins need >2 samples and >1 valid point after clipping. The wavelength grid is fixed/linear, 0.7–5 µm with half-bin-width stepping (overlapping bins), hard-coded and not release- or band-aware. **Output**: two `astropy.table.Table`s from `extract_spectrum()` (~line 890) — a per-exposure table (`lam_int`, `flux_int` in mJy, `good` flag) and a binned table (`lam_bin`, `flux_bin`, `lamerr_bin`, `fluxerr_bin`); optionally written to a 3-HDU FITS file.

## Reusable pieces for our project

- `search_lvfs()` (~line 88) / `tap_search()` (~line 158): a clean, retry-wrapped ADQL/TAP query pattern against `spherex.artifact`/`spherex.plane`, including the `MAXREC` overflow-warning pattern — a directly reusable starting point for our own discovery layer.
- `get_links()` (~line 33): IRSA-URL vs S3-URI construction from a TAP `uri` column — a convenient minimal reference for dual-path retrieval.
- `process_cutout_s3()` (~line 178): a solid template for `Cutout2D`-based cutout extraction directly from S3-hosted parent MEFs with `fsspec`, including correctly recomputing/writing the cutout WCS — should be extended to also carry FLAGS/VARIANCE/PSF-or-EPSF/ZODI/Solid-Angle cutouts.
- `create_multiFITS()` (~line 502): a useful pattern for bundling per-exposure cutouts plus a `CUTOUT_INFO` summary table into one on-disk MEF product per target — extend to preserve the extensions this repo drops.
- `load_flag_info()`/`decompose_flags()`/`check_flags()` (~lines 1101–1186): a clean bitmask-decomposition and "reject if disallowed bit set" pattern; the flag table itself must not be reused as-is (QR-era, hard-coded), but the logic is a fine template once rewired to read `MP_*`/`MSKN`/`MSKM` dynamically from the header.
- `bin_spherex_flux()`/`bootstrap_median_std()` (~lines 767–864): a serviceable fallback/sanity-check combination method, though our pipeline will want inverse-variance weighting from propagated per-pixel errors rather than an unweighted bootstrap-of-the-median.
- `tutorial/main.md`: a good worked example of the discovery → cutout → bundle → extract → plot workflow, useful for validating our own TAP queries and coordinate handling, even though the photometry method it demonstrates is not what we need for resolved galaxies.

## Risks and limitations

Point-source-only, fixed-aperture-only — no path to Sersic/extended-source modeling; adapting for resolved/semi-resolved post-starburst galaxies means writing essentially all new photometry/modeling code, with this repo supplying only data-access and combination scaffolding. No PSF/EPSF handling at all, so no reusable PSF-forward-modeling logic or guidance on the QR2→QR3 PSF transition. Wavelengths rely on WCS-WAVE-style WCS rather than CWAVE/CBAND, flagged as the less-authoritative source. VARIANCE is downloaded but unused; no formal per-pixel error propagation and no 3% systematic term, so reported uncertainties (bootstrap scatter only) likely mis-characterize the true error budget, especially for single/few-exposure bins. Fixed 6.15″ pixel scale ignores real solid-angle variation. Hard-coded QR-era flag table with no dynamic header parsing will silently mis-map or miss flags under QR3/DR1. No license file — reuse should be confirmed with the author or reimplemented rather than copied wholesale. No tests, packaging, CI, or dependency manifest; single author, 2 weeks of commit history, no activity in the ~5 weeks since the last commit — looks like a personal/exploratory scratch tool, not a maintained package. `fsspec` is imported lazily inside `process_cutout_s3` with no module-level import, so using it outside the tutorial's own import context would raise `NameError`.

## Verdict

**Read for ideas only.** The TAP/S3/IRSA data-discovery-and-retrieval scaffolding (`search_lvfs`, `get_links`, `process_cutout_s3`, `create_multiFITS`) is a reasonable, concrete reference for wiring up our own SPHEREx data-access layer, and the flag-decomposition logic is a fine pattern to adapt. But the core extraction method — fixed circular-aperture photometry on point sources, no PSF model, no Sersic/extended-source support, no VARIANCE-based error propagation, hard-coded QR-era flags, WCS-based (not CWAVE/CBAND) wavelengths — is a poor match for a PSF-forward-modeling, background-modeling, and stacking pipeline targeting unresolved-to-resolved post-starburst galaxies. Despite the author's SDC affiliation, the repository states no connection to the official IRSA Spectrophotometry Tool or Level 3 Tractor forced-photometry catalogs, so it should not be treated as a stand-in or prototype for that tool.
