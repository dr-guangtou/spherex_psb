## Purpose and scope

Xcavation performs forced circular-aperture photometry at a user-supplied (RA, Dec) on individual SPHEREx Level-2 QR2 MEF images, stepping through every exposure overlapping that sky position (found via an IRSA TAP query) to build a wavelength-vs-flux table — a per-exposure "spectrum" assembled from many single-band aperture measurements, not a stacked/coadded one. The single entry point, `genspec(ra, dec, config)`, multi-threads this per-exposure photometry and returns a `pandas.DataFrame` with one row per exposure, optionally saving a QA finder-chart PDF and an ASCII spectral table. Built-in proper-motion propagation signals a **point-source** design target (moving/field objects like ultracool dwarfs), not resolved or semi-resolved galaxies. There is no moving-object orbit search, mosaic/map building, or multi-object batching beyond looping `genspec` per target.

## Data access layer

Queries the **IRSA TAP service** directly (`pyvo.dal.TAPService`, `genspec.py:431`) with a hand-written ADQL query (`genspec.py:434-441`) joining `spherex.artifact`/`spherex.plane`, filtered with `CONTAINS(POINT('ICRS', ra, dec), p.poly)`, then builds a **server-side cutout URL** by appending `?center=...&size=...` to the artifact's IRSA URI. The comment directly above the query reads `# Query SphereX QR2 (Will Need Updates)` (`genspec.py:433`) — the author already flags the schema as QR2-specific. No SIA/IBE calls, no direct S3 access. No caching: every `genspec` call re-queries TAP and re-downloads every overlapping image (optionally straight into RAM via `requests.get`+`BytesIO`, `aperture.py:106-113`). Detector number is inferred by parsing it out of the returned URL string (`genspec.py:448-462`) rather than from a header keyword.

## Data model handling

`spherex_aperature_phot` (`aperture.py:50-384`) opens the FITS file with `fits.open(url, lazy_load_hdus=True)` and mixes name-based and position-based HDU access: `hdul["IMAGE"].header` (`:122`) but `hdul[1].data`/`.header` for the actual array/WCS (`:138,142`, assuming IMAGE=HDU 1); `hdul['FLAGS'].data` and `hdul['VARIANCE'].data` by name (`:131,151`); **ZODI** by position only, `hdul[4].data` (`:144`) — will silently break or read the wrong extension if ordering changes across releases. **PSF/EPSF**: never opened; only the scalar header keyword `hdul[1].header['PSF_FWHM']` (`:212`) is read to size apertures, so there is zero code path distinguishing the QR2 121×101×101 PSF cube from the QR3 33×33 EPSF table, and no PSF sampling/normalization logic to build on. **Wavelengths** come from **WCS-WAVE**, not CWAVE/CBAND: `WCS(spectral_header, fobj=hdul, key="W")` (`:139`), then `pixel_to_world` over the full grid with the value nearest the target pixel picked (`:336-347`) — less accurate than the authoritative per-column calibration files, which are never touched. **ZODI** handling is a simple optional subtraction, `flux_image_temp - zodi_image_temp` (default on, `:143-147`), with no scaling/model fitting. **VARIANCE** is propagated through aperture photometry of the variance array plus background variance (see Photometry). **Solid Angle map**: not read; a single hard-coded pixel scale (`pixel_scale_deg = 0.001708333`, `:123`) is used instead, ignoring focal-plane-dependent pixel-scale variation. **Cutout-to-parent mapping**: none in Python — `Cutout2D` is imported (`:33`) but never called; the code trusts the IRSA server's `size=`-parameter cutout and does all WCS math in that array's own frame, with no explicit offset bookkeeping.

## Photometry / extraction method

**Forced circular-aperture photometry only** via `photutils` (`aperture.py:217-306`); no PSF fitting, no Tractor-style forced photometry anywhere. Aperture/annulus radii are user-configurable multiples (defaults 2, 3.5, 10) of the single `PSF_FWHM` header value (`:215-226`) — no PSF shape/sampling, subpixel shift, downsampling, or normalization logic to reuse. Background is a local-annulus estimate via `SigmaClip`+`ApertureStats` (mean/median/mode, `:231-243`), scaled by good-pixel aperture area (`:246-275`) — a classic annulus estimator, not a 2D model. No deblending. Error propagation: `flux_err = sqrt(var_flux_ap + area**2 * var_bkg_per_pix)` (`:301-306`), with no additional systematic term (contrast with the IRSA tool's 3% systematic in quadrature). Masking (`clean_type`): `none`/`mask`/`median_mask`(5×5 median fill)/`interp_mask` (`griddata` fill) (`:169-196,244-298`); bad-bit lists are user-supplied integers plus a hard-coded `total_bad_bits` list (`:319-321`) implicitly tied to QR2's `MP_*` scheme, never derived from header flag names. **No stacking/coaddition** — `genspec` loops (multi-threaded, `genspec.py:469-524`) over every overlapping exposure and appends one row per exposure; the "spectrum" is a scatter of single-epoch measurements the user must bin themselves. **Output**: a `DataFrame` with `wavelength, delta_lambda, flux, flux_err, flag_count, flag, SNR, ...` (one row/exposure); optional ASCII table (`genspec.py:564-596`) and a QA finder-chart PDF. The live spectrum plot (`quality.spectra_plot`) only calls `plt.show()` and is never saved to disk.

## Extended-source support

None. No Sersic fitting, no elliptical aperture option, no aperture-correction machinery, no galaxy morphology handling anywhere in the four source files. The aperture is always a circle on a single proper-motion-corrected sky position, sized off the point-source PSF FWHM — fundamentally point-source-only and not directly usable for resolved/semi-resolved post-starburst galaxies.

## Code quality

Flat structure: four modules under `xcavation/` (`aperture.py` 385 lines, `genspec.py` 644, `motion.py` 137, `quality.py` 263; ~1440 total), heavily comment-banded with docstrings on every public function, but logic is monolithic (e.g. `spherex_aperature_phot`/`genspec` each handle I/O, WCS, photometry, and output formatting in one large function). Dependencies listed in `requirements.txt`/`setup.py` include scikit-learn, xarray, h5py, emcee, corner, pathos, and astroquery — **none of which are actually imported** anywhere in the source, suggesting leftover/aspirational dependencies. Hard-coded values: pixel scale (`aperture.py:123`), the QR2-flagged TAP query (`genspec.py:433`), position-based HDU indexing for IMAGE/ZODI, and a QR2-tied flag-bit enumeration. Robustness to QR3: low — since PSF/EPSF is never read, the EPSF format change wouldn't crash the tool but also gains nothing from it (FWHM-only sizing keeps "working" if `PSF_FWHM` still exists); the hard-coded flag-bit list and position-based ZODI/IMAGE HDU access are the likelier QR3 breakage points if extension order or flag semantics change under `MSKN`/`MSKM`. No tests anywhere.

## Reusable pieces for our project

- `xcavation/motion.py` (full file, 137 lines): self-contained `decimal_year()`, `time_mjd()`, `proper_motion()` utilities for propagating coordinates to each exposure's epoch — clean boilerplate if point-like nuclear components ever need motion handling.
- `genspec.py:427-444`: a working ADQL/TAP query template against `spherex.artifact`/`spherex.plane` for discovering overlapping L2 exposures, plus the IRSA server-side cutout URL pattern — a reasonable starting point for a data-discovery layer, but needs verification against QR3's TAP schema before reuse.
- `genspec.py:254-294` (`retry()`): a small, generic retry wrapper handling HTTP 502s — reusable as-is for robust batch downloading.
- `aperture.py:231-243`: pattern for a local annulus background estimate (`SigmaClip`+`ApertureStats`) — a minimal template, though it would need generalizing beyond circular annuli for galaxy work.
- `quality.py` (`finder_chart()`, `spectra_plot()`): multi-panel per-wavelength cutout QA plotting with aperture/annulus overlays — reusable scaffolding for diagnostic figures, independent of the underlying photometry method.
- `aperture.py:169-196` (`interp_mask`/`median_mask` branches): simple bad-pixel interpolation patterns that could inform (not directly reuse) a bad-pixel handling step ahead of PSF forward modeling.

## Risks and limitations

Point-source only (no Sersic/galaxy support, no elliptical apertures, no aperture corrections) — disqualifying as an extraction engine for resolved/semi-resolved galaxies, at best usable for an unresolved-nucleus check. QR2 hard-coded throughout (TAP query, flag-bit enumeration), with the author's own comment flagging the need for updates and no QR3 EPSF/MSKN-MSKM support. No PSF forward-modeling substrate since PSF/EPSF is never read. Wavelengths from WCS-WAVE rather than CWAVE/CBAND. No stacking/coaddition — users must implement their own binning and error weighting. No systematic error term. No tests/CI and a template-only Sphinx doc skeleton; several unused dependencies suggest incomplete side branches. Small, young project (3 stars, 1 fork, ~8 months of history) tied to a short RNAAS note rather than a full methods paper. The live spectrum plot is not persisted to disk even when `save_data=True`.

## Verdict

**Borrow pieces.** Xcavation's extraction method — forced circular-aperture photometry sized by a single PSF-FWHM value, WCS-WAVE wavelengths, per-exposure (non-stacked) output, and zero extended-source or PSF-cube/EPSF support — is a poor match for PSF forward modeling, background handling, and stacking across unresolved-to-resolved post-starburst galaxies, and the QR2-only assumptions add real adaptation risk for QR3/DR1. Several small, self-contained utilities are genuinely reusable as starting points: the IRSA TAP discovery pattern, the retry-with-backoff wrapper, the proper-motion functions, the local sigma-clipped annulus background estimator, and the QA plotting scaffolding. Treat it as a source of small code fragments and a useful negative example of what a from-scratch pipeline must add: PSF/EPSF ingestion, CWAVE/CBAND wavelengths, galaxy morphology support, exposure stacking, and a QR3-aware flag scheme.
